# DP.D.296 Настройки хостинг-платформы ≠ содержимое репозитория

## Правило

Признак вроде «этот репозиторий — шаблон» (`is_template`) — настройка самой хостинг-платформы (GitHub/GitLab/Railway/Vercel), не файл в дереве репозитория. Её сброс (вручную, автоматизацией платформы, миграцией организации) не порождает ни коммита, ни diff'а, ни строки в истории, которую можно прочитать при расследовании.

## Живой случай

`is_template` флаг `FMT-exocortex-template` сброшен — сломал `fork_platform_template` 404-кой. Симптом проявился только у потребителя, без единой зацепки в коде или git log. Фикс — через GitHub API + сторож дрейфа на будущее.

## Тест

«Поведение кода/конвейера зависит от настройки хостинг-платформы (флаг, права, webhook-конфиг), а не от файла в git-дереве?» Да → «посмотреть git log» здесь принципиально не поможет; нужен явный сторож дрейфа — периодическая сверка через API платформы с ожидаемым значением.

## Применимо к

Любая настройка хостинг-платформы (GitHub/GitLab/Railway/Vercel и т.п.), от которой зависит поведение кода или конвейера.
