# DP.M.427 — Новый шаг установки регистрировать в обеих точках входа

## Определение

Конвейер с двумя точками входа (первичная установка / обновление существующей инсталляции): каждый новый шаг устанавливается в обе точки или в общий код, вызываемый из обеих. Шаг, добавленный только в путь первичной установки, структурно недостижим на уже настроенных машинах — именно тех, которые с этого момента получают только обновления, не переустановку с нуля.

## Живой случай

Новый шаг установки (расписание конвейера вычленения знаний) добавили только в `setup.sh` — логичный выбор для новых инсталляций, но именно поэтому он был недостижим на всех уже существующих машинах. Баг проявился ровно там, где по построению не мог не проявиться — не на новой машине, а на старой. Фикс — тот же шаг вызывается ещё и из цепочки post-apply обновления, идемпотентно (пропускает уже загруженную неизменную задачу вместо unload/load).

## Тест обнаружения

«Тестировали ли новый шаг установки ТОЛЬКО через "установить с нуля"?» Да → путь обновления в проверке не участвовал и систематически не мог обнаружить эту дыру.

## Применимо к

Любой конвейер с раздельными путями «первичная установка» и «обновление существующей инсталляции».
