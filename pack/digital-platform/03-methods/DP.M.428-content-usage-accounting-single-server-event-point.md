# DP.M.428 — Схема учёта обращений к контенту для будущих отчислений авторам

> **TODO (открыто, не блокирует запись карточки):** capture-источник сам помечает «сверить с PACK-ecosystem на приёмке» — сверка ещё не выполнена, следующему читателю карточки стоит проверить пересечение с методами PACK-ecosystem перед использованием как готового эталона.

## Определение

Задача «сколько раз обращались к контенту, чтобы когда-нибудь платить автору» решается не единичным счётчиком, а архитектурой из трёх частей:

1. **Событие фиксированной формы** — проверенный принципал, серверное время, id+версия/хэш контента, нормализованный код причины без сырого текста запроса, канал, trace_id, исход, дедуп-ключ.
2. **Инвариант «один вход»** — ЛЮБОЙ путь чтения контента (кэш-хит, admin/debug, batch, async job, MCP-инструмент, суммаризатор) обязан порождать событие либо блокируется. Обходов нет.
3. **Лестница внедрения** V0 (ретроспектива без разработки) → V1 (статистика подключений) → V2 (события обращения) → V3 (расчёт вознаграждения) → V4 (атрибуция на уровне цитаты) — каждая ступень требует явного gate (например, coverage-аудит путей чтения ≥99% перед переходом V2→V3), не включается по умолчанию.

## Приватность

Встроена с V0: `reason_code` enum вместо сырых запросов, псевдонимизация, k-anonymity в отчётах авторам, разделение операционного и денежного контуров.

## Тест обнаружения

«Проектируем доступ к чужому контенту, который когда-нибудь может стать платным?» Да → спроектировать событие использования и инвариант «единой точки без обходов» ДО появления самой денежной механики — иначе новые пути чтения (async/batch/кэш) появляются быстрее, чем телеметрия успевает их покрыть, и расчёт вознаграждения будет считаться по заведомо неполным данным.

## Применимо к

Любая система, планирующая монетизацию доступа к чужому контенту (Pack, база знаний, курс) с несколькими путями чтения.
