# DP.M.431 — Список триггерных стемов в naming-гейте: обязательная граница слова

## Определение

Хук-предупреждение об именовании артефакта, запрограммированный списком стемов-глаголов, собранным на момент написания, стареет: новые легитимные формулировки задачи не попадают в список и молча проходят без предупреждения. При добавлении недостающих стемов простое совпадение подстроки создаёт новый класс ложных срабатываний на системные существительные с тем же префиксом.

## Живой случай

Хук предупреждал только про 17 старых стемов действий, но не про три канонических примера из текста самого Артефактора («Разбор X», «Анализ X», «Проверка X») и найденный живьём случай «Подключение X» — все четыре молча проходили бы commit без предупреждения. Наивное расширение списка новыми стемами создало бы ложные срабатывания на «Анализатор логов», «Проверочный стенд» (совпадение по префиксу).

## Структура фикса

Держать обе группы разными правилами: старая — без изменений, новая — с обязательной границей слова (пробел/пунктуация/конец строки) после стема.

## Переносимый принцип

Список триггерных стемов в текстовом guard/naming-гейте нужно расширять регулярно (список стареет быстрее, чем его вспоминают обновить), и каждое новое добавление обязано матчиться с anchoring границы слова, а не голой подстрокой — иначе исправление одного класса ложных отрицательных срабатываний создаёт новый класс ложных положительных.

## Тест обнаружения

«Naming-гейт матчит триггерный стем голой подстрокой, без anchoring границы слова?» Да → либо не ловит новые легитимные формулировки (список устарел), либо ловит системные существительные с тем же префиксом.

## Применимо к
Любой текстовый guard/naming-гейт, матчащий список триггерных слов против свободного текста.
