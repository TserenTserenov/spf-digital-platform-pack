# DP.FM.400: Платформенно-специфичный примитив без проверки наличия — тихий no-op на неподдерживаемой платформе

## Симптом
Публикация журнала одного из хостов молча перестала попадать в git — ни ошибки, ни лога, ни диагностики.

## Причина
Публикатор журнала полагался на `systemd`/`systemctl` как на примитив запуска фоновой задачи, общий для всех хостов конвейера. На macOS, где `systemctl` физически отсутствует, вызов молча ничего не делал.

## Антипаттерн → Паттерн
- **Антипаттерн:** вызов платформенно-специфичного примитива (systemd, cron, launchd, конкретный бинарник) без проверки его наличия — на отсутствии молча no-op.
- **Паттерн:** на отсутствии примитива — либо явный fail, либо зафиксированный fallback (здесь — прямой запуск в фоне с rate-limit файлом последнего кика и собственным flock как второй защитой от параллельных запусков).

## Тест обнаружения
«Код вызывает платформенно-специфичный примитив без проверки `command -v`/наличия?» Да → тихий no-op на неподдерживаемой платформе неотличим от «всё хорошо, публиковать нечего».

## Применимость
Любой кроссплатформенный конвейер, вызывающий системно-специфичный примитив (systemd/cron/launchd/бинарник) без явной проверки платформы.
