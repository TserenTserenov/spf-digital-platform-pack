# DP.FM.405: Персонализированное представление через клиентский фильтр над глобальным листингом

## Симптом
Экран «что доступно купить/использовать» молча прятал часть законно доступных записей для затронутого пользователя — без единой ошибки, просто более короткий список.

## Причина
Экран брал ГЛОБАЛЬНЫЙ каталог-эндпоинт плюс клиентский фильтр по дате (`started < today`), задуманный убрать устаревшие записи, но часть записей законно остаётся в продаже/доступе после номинальной даты старта (поток с открытым набором, rolling-серия) — общий фильтр молча прятал их.

## Антипаттерн → Паттерн
- **Антипаттерн:** персональное/scoped представление строится наложением клиентского фильтра-эвристики (дата, статус, категория) на ГЛОБАЛЬНЫЙ листинг-эндпоинт.
- **Паттерн:** предпочитать персонализированный/scoped эндпоинт, кодирующий доступность на сервере, реконструкции её на клиенте фильтрами (референсная реализация того же домена уже использовала такой эндпоинт).

## Тест обнаружения
«Экран доступности строится клиентским фильтром поверх глобального каталога?» Да → эвристики фильтра рано или поздно разойдутся с истинным множеством «доступно этому пользователю».

## Применимость
Любой экран/API, показывающий персонализированную доступность через клиентский фильтр над общим листингом.
