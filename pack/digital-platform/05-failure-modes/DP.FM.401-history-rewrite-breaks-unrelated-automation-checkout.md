# DP.FM.401: Force-push с переписыванием истории не инвентаризирует все чекауты репозитория

## Симптом
Расхождение оставалось незамеченным восемь дней — публикация в этом же окне и так молча no-op'илась по независимой причине (DP.FM.400), два несвязанных отказа маскировали друг друга.

## Причина
После вынужденного переписывания истории (утечка секрета → filter-repo + force-push) любой чекаут, не участвующий в обычном цикле pull/rebase активной рабочей сессии (отдельный автоматизационный чекаут для фоновой публикации журнала), расходится с origin по построению и конфликтует на каждой попытке синхронизации без сообщения об истинной причине.

## Антипаттерн → Паттерн
- **Антипаттерн:** force-push с переписыванием истории затрагивает только рабочие копии активных сессий, отдельные автоматизационные/CI-чекауты не проверяются.
- **Паттерн:** force-push с переписыванием истории обязан сопровождаться инвентаризацией ВСЕХ чекаутов репозитория — пересоздать заново или явно проверить сразу после rewrite.

## Тест обнаружения
«После filter-repo+force-push проверены ТОЛЬКО рабочие копии активных интерактивных сессий?» Да → отдельные автоматизационные/CI-чекауты, синхронизирующиеся не через обычный pull, остаются расходящимися незамеченно.

## Применимость
Любой репозиторий с несколькими независимыми чекаутами (рабочие копии + автоматизационные/CI-копии), где произошёл force-push с переписыванием истории.
