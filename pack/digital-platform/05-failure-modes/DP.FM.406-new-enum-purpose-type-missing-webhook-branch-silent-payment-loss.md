# DP.FM.406: Обработчик, ключуемый по типу, не аудирован при добавлении нового значения enum

## Симптом
Платёж прошёл, деньги списаны, пользователь не получил ничего — ни одной ошибки нигде не всплыло, код доставки просто никогда не запускался.

## Причина
Завершение оплаты было реализовано как вебхук-управляемое для двух типов назначения (SEMINAR, WORKSHOP); когда добавили третий тип (INTERNSHIP), никто не добавил соответствующую вебхук-ветку, а поллинг-фоллбэк (которым эта дыра была закрыта в старом боте) в новом боте не был реализован вообще ни для одной внутренней покупки.

## Антипаттерн → Паттерн
- **Антипаттерн:** обработчик завершения/уведомления, ключуемый по перечислимому полю «тип», без аудита каждого обработчика при добавлении нового значения; вебхук-only дизайн без запасного варианта на случай, если апстрим не шлёт событие для какого-то типа.
- **Паттерн:** (1) добавление нового значения в перечисление требует аудита каждого обработчика, ключуемого по нему; (2) defense in depth — таблица отслеживания + поллинг-фоллбэк; (3) при разбиении «пометить готовым» + «уведомить» на два шага — уведомление должно идти первым: крах посередине обязан склоняться в сторону «уведомление ушло, статус ещё не помечен» (безопасно сверить повторно), не наоборот.

## Тест обнаружения
«Обработчик завершения ключуется по enum-полю "тип/назначение", и есть вебхук-only дизайн без фоллбэка?» Да → добавление нового значения enum без аудита каждого потребителя даёт молчаливый и денежный пробел.

## Применимость
Любая система обработки асинхронных событий (платежи, доставка), ключуемая по расширяемому enum-полю.
