# DP.FM.402: Путь, правящий пользовательское состояние, вызван и из разового, и из периодического кода

## Симптом
Пойман холодным ревью до деплоя — первый вариант при каждом обновлении переписывал бы пользовательский глобальный git-хук и указатель шаблонов.

## Причина
Конвейер вычленения знаний завели через тот же путь кода, что и обычную установку роли, — включая шаг, который правит глобальные пользовательские настройки git. Путь стал вызываться ещё и по расписанию обновления, а не только один раз при первой установке.

## Антипаттерн → Паттерн
- **Антипаттерн:** шаг установки, трогающий состояние, потенциально изменённое пользователем ПОСЛЕ установки (глобальные хуки, конфиги, шаблоны), вызывается без разбора из пути, выполняющегося больше одного раза за жизнь инсталляции.
- **Паттерн:** разовые и периодические действия одного конвейера явно разделены (здесь — флаг `--schedule-only`).

## Тест обнаружения
«Шаг установки правит состояние, которое пользователь мог изменить после установки, и вызывается из пути, срабатывающего периодически?» Да → риск молчаливой перезаписи чужой кастомизации на каждом плановом тике.

## Применимость
Любой установщик/обновитель, где шаг первичной установки правит глобальное пользовательское состояние и вызывается также из периодического пути (обновление, расписание).
